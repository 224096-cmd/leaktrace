# LeakTrace（リークトレース）

個人情報漏えいの仕組みと対策を、攻撃と防御の両方の体験から学ぶWeb教材です。

- 公開URL: https://224096-cmd.github.io/leaktrace/
- 完全クライアントサイド（サーバー不要）。入力は外部に送信しません。一度開けばオフラインでも動作します。
- 扱うデータはすべて架空です。実在の人物・企業・サービスは登場しません。
- 想定端末：タブレット・PC（スマホでも表示可）

## 構成

各ステージは「①見る → ②破る → ③なぜ守れるか」の三段構成です。

| ステージ | ①見る | ②破る | ③なぜ守れるか |
|---|---|---|---|
| 1 パスワード | SHA-256 によるハッシュ化を実際に計算 | 架空の流出リストでリスト型攻撃 | 多要素認証で停止／端末の計算速度を実測し解読時間を推定 |
| 2 フィッシング | URL の本当のドメインを色分け表示 | 偽メールの要素を選び「だまされやすさ」を確認 | 本物/偽物の判別課題（自動採点） |
| 3 侵入の連鎖 | 侵入→探索→権限奪取→DB到達→持ち出しの連鎖を再生 | 攻撃者として連鎖をたどる | 対策を置き、どこで断ち切れるかを確認 |
| 4 人為ミス | CC と BCC の違い | 時間制限つきの一斉送信 | 「確認なし／確認あり」の2条件で学習者が実際に送信を試行し、ミス率を比較 |
| 最終課題 | 自分の行動を選び、攻撃経路マップと結びつける | | |

学習層：導入（中学生〜）／体験（高校生〜）／探究（大学生〜）。説明の深さと記述課題が切り替わります。

## 評価のための機能

- **はじめのテスト／おわりのテスト**（`#/test/pre`・`#/test/post`）：同じ問題を順番を変えて出題。はじめのテストでは正誤を表示しない。
  - 知識問題：`data/test-items.json` に研究者が作成して追加する（空なら出題しない）
  - メールの判別：ステージ2の判別問題（本物／偽物）
  - 理解の自己評価・行動意図：各4項目、5段階
- **使いやすさアンケート**（`#/survey`）：SUS（10項目、0〜100点に換算）と自由記述
- 学習の流れ：はじめのテスト → ステージ1〜4 → 最終課題 → おわりのテスト → アンケート

### 知識問題の追加方法

`data/test-items.json` の `items` に次の形で追加します（`ans` は正解の番号。最初の選択肢が 0）。

```json
{ "id": "k1", "cat": "know", "q": "問題文", "opts": ["選択肢A", "選択肢B", "選択肢C"], "ans": 1 }
```

`cat` は `know`（知識）または `action`（行動の判断）。学習者には自動で「わからない」の選択肢が付きます。

## 学習記録

「学習記録」画面から、まとめ Markdown・操作ログ CSV・実測値 CSV・テストとアンケート CSV・全データ JSON を書き出せます。記録は端末のブラウザ内（localStorage）にのみ保存されます。

## 倫理・法令

攻撃の体験は模擬環境の中でのみ成立する簡略化した操作であり、現実のシステムに使える手順は含みません。パスワードの解読時間は、実際に解読するのではなく「組み合わせ総数 ÷ 実測した計算速度」で見積もります。教材冒頭で不正アクセス禁止法と学習の目的を説明し、同意してから始めます。
